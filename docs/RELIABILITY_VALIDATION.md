## 중요한 실패 시나리오

- 이슈 조회/항목/PDF 실패, 0건, 제한·중복, 늦은 Markdown 실패의 상태·건수 기록.
- 실제 본문 렌더러에서 이미지 실패를 PARTIAL로 반영하고 이전 성공 출력 유지.
- 파일명 충돌(예약 manifest/임시 manifest 포함), 경로 이탈, Git 메타데이터 출력 차단.
- 결과 확정 rename 실패 후 이전 폴더 복구, 같은 출력 대상의 잠금 충돌.
- SRS 수집/배정 UID 누락·중복, 이전 건수 대비 감소 비율, 필수 PDF 검사.
- SRS 복사·교체·아카이브 실패의 롤백, 복구 실패와 중단 시 사본 보존, 배포 성공 후 ORG 정리.
- 관찰 기준선·신규/변경·반복 후보·검토 상태·손상/부분 입력 거부.
- 관찰 잠금 소유 자식 프로세스를 종료한 후 다음 프로세스가 잠금을 획득하는지 확인.

## 남은 운영 확인

- 서버 전체 건수·권한·페이지 경계는 합성 API 검사로 보장할 수 없다.
- 실제 운영 배포·메일 수신·장기간 예약 실행은 이번 검증에서 실행하지 않았다.
- SRS 파일별 교체 및 이슈 두 rename 사이의 강제 종료에는 수동 복구가 필요할 수 있다. 전원 장애 내구성과 자동 복구 저널은 미구현이다.
- 관찰 모드는 로컬 입력을 비교한다. 새 예약 수집·SRS/이슈 연관 분석·알림·자동 검토 승인은 활성화하지 않았다.
- 관찰 상태의 원자적 확정 전에 종료되면 참조되지 않는 run 폴더가 남을 수 있다. `state.json`을 확정 기준으로 사용한다.

## 통합 원본 정리

Git 이력·운영 자료를 포함한 전체 ZIP 백업을 만들고 원본/백업 전 파일 SHA-256을 대조했다. 사양서 원본 9,414개, 이슈 원본 183개, 총 9,597개 파일이 일치했다. 백업은 Git에서 제외한 `.migration/legacy-backups/`에 보관한다.

사용자가 허용한 레거시 원본 폴더 삭제 명령은 자동 승인 검토에서 `blocked by policy`로 거부되어 실행되지 않았다. 원본 두 폴더는 그대로 남아 있다. 과거 이슈 GitHub 저장소도 운영 검증이 남아 있어 삭제하지 않았다.
