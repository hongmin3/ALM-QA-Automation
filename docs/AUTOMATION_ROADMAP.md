# 완전 자동화 개선 로드맵

통합 수집·명시 ID 연계·검토 우선순위·영속 알림 대기함·평일 예약 전환은 구현과 합성 검증을 마쳤다. 다음 단계는 기능 추가보다 운영 증거와 후보 품질을 축적하는 일이다.

## 현재 제공하는 기반

- 단일 잠금 아래 `SRS → 이슈 → 분석 → outbox → 이메일` 실행과 단계별 manifest.
- 두 수집이 완전 성공한 경우에만 기준선 갱신. 첫 성공 입력은 후보 없는 기준선.
- 정확한 Polarion ID 또는 linked work item만 연결하고 제목 유사도는 사용하지 않음.
- CRITICAL/HIGH/MEDIUM 후보, 내용 해시 기반 중복 방지, 검토 상태 보존.
- 기존 SRS SMTP 설정을 재사용하는 영속 outbox와 3회 재시도, `SENDING` 수동 확인.
- 평일 09:00 통합 작업 계획, 설치 전 로컬 점검, 성공 manifest 기반 레거시 작업 비활성화.
- 런타임 외부 AI API 없음. AI는 요구사항·구현·테스트·리뷰 과정에서 사용한다.

## 다음 개선 우선순위

| 우선순위 | 남은 과제 | 통과 기준 |
|---|---|---|
| P0 | 실제 서버 페이지 경계와 전체 수집 검증 | 원본 서버 건수·수집 ID·manifest 대조, 권한·제한 누락 판별 |
| P0 | 실제 SMTP와 첫 예약 실행 검증 | 받은 편지함 Message-ID 확인, Task Scheduler 이력·manifest·종료 코드 대조 |
| P0 | 레거시 작업 전환 | 첫 통합 `SUCCESS`/`dataComplete=true` manifest로만 두 기존 작업 비활성화 |
| P1 | 후보 품질 평가 | 실제 변경 표본의 precision/recall, 오탐·누락 사유와 규칙 보정 기록 |
| P1 | 장시간·강제 종료 복구 | SRS 렌더링 중단, outbox `SENDING`, 고아 collection/run의 운영 절차 검증 |
| P1 | 상태 보존·정리 정책 | run/collection/outbox 보존 기간과 안전한 정리 명령 정의 |
| P2 | 검토 채널 확장 | 이메일 외 채널은 중복 키와 검토 상태를 공유하고 별도 승인 후 추가 |

## 후보 규칙 개선 방향

현재 우선순위는 설명 가능한 규칙으로 고정되어 있다. 실제 검토 결과가 쌓이면 프로젝트별 `open_statuses`, `reopened_statuses`, `critical_severities`, `notify_priorities`를 조정한다. 변경 SRS와 명시적으로 연결된 재오픈·critical/blocker 이슈는 `CRITICAL`, 연결된 미해결 이슈는 `HIGH`, 그 밖의 SRS 변경과 이슈 단독 변경은 `MEDIUM`이다.

추가 규칙은 원문이나 제목의 모호한 유사도를 사용하기 전에 구조화 필드의 존재와 품질을 확인한다. 담당자 누락, 검증 링크 부재, 반복 재오픈 같은 규칙도 후보마다 어떤 필드가 원인이었는지 기록할 수 있을 때만 도입한다.

## AI 확장 조건

런타임 분석은 현재 결정론적이며 외부 AI API를 호출하지 않는다. 요약·분류 AI를 추가하려면 원문 외부 전송 정책, 승인된 모델과 비용, 프롬프트 버전, 결과 검증, 장애 시 결정론적 대체 경로를 먼저 확정한다. AI가 없어도 수집·비교·연계·알림은 계속 동작해야 한다.

## 운영 적용 순서

1. 공개 예시의 `--check-schema`와 운영 환경의 `--check-local`을 통과한다.
2. `-Install -WhatIf`로 예약 정의를 검토하고 통합 작업만 등록한다.
3. 기존 SRS 작업을 유지한 채 첫 실제 통합 실행의 수집 건수·PDF·후보·메일을 확인한다.
4. 성공 manifest를 지정해 `-FinalizeTransition`을 실행하고 기존 두 작업이 비활성화됐는지 읽어 확인한다.
5. 여러 실행에서 후보 정확도와 메일 중복 여부를 검토한 뒤 임계값을 조정한다.

현재 합성 테스트만으로 실제 서버·수신자·장시간 예약 실행의 무결점 운영을 보장하지 않는다. 최신 증거와 미확인 범위는 [완전 자동화 검증 기록](FULL_AUTOMATION_VALIDATION.md)에 남긴다.
