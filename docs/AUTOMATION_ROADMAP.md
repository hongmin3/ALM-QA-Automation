# 완전 자동화 제안과 기존 기능 개선 검토

관찰 모드까지 구현했고, 통합 예약 수집과 새 알림은 아직 활성화하지 않았다.

## 권장 흐름

예약 실행 → SRS·이슈 수집 → 수집 완전성 검증 → 이전 실행과 비교 → 검토 후보 저장 → 신규·중요 후보 요약 알림 → 사용자 검토 상태 기록.

공통 실행 메뉴는 유지하고, 다음 단계에서 공통 실행 결과·실행 이력·알림 인터페이스를 먼저 만든다. 서로 다른 렌더러를 즉시 합치는 것보다 기존 동작을 보존하면서 자동화의 신뢰도를 높이는 효과가 크다.

## 현재 제공하는 기반

- 이슈 실행 ID·OS 잠금·임시 출력·이전 성공본 백업, SUCCESS/PARTIAL/FAILED와 종료 코드 0/4/1.
- 0건·제한·중복·빈 ID·본문 이미지 실패·PDF 실패 기록. searchedCount는 반환 목록 수이며 서버 전체 수의 독립 검증은 아님.
- SRS 수집/배정 ID 대조, 감소 비율·필수 PDF 검사, 처리 가능한 배포 I/O 실패 복구와 성공 후 ORG 정리.
- 서버 접속을 포함하는 `--check`와 로컬 전용 `--check-local` 구분.
- 관찰 모드: 저장 파일의 신규·변경 근거, 후보 중복 방지, NEW/IN_REVIEW/DONE/EXCLUDED 저장. 알림 없음.

## 다음 개선 우선순위

| 우선순위 | 남은 과제 | 통과 기준 |
|---|---|---|
| P0 | 실제 서버의 페이지 경계·전체 수집 검증 | 원본 서버 건수와 수집 ID 대조, 제한/권한 누락 판별 |
| P0 | 관찰 후보 품질 검토 | 여러 실제 실행의 변경 전후를 사용자 검토와 대조 |
| P1 | SRS 조기 실패 알림 및 발송 대기함 | 수집 성공/알림 성공 분리, 발송 실패 후 제한적 재시도·중복 방지 |
| P1 | 통합 예약 수집 및 일시 실패 재시도 | 기존 CatchUp 정책과 충돌 없이 실행, 재수집과 알림 재전송 분리 |
| P1 | 강제 종료 복구와 보존 기간 | staging/previous 복구 절차 검증, 안전한 백업 정리 |
| P2 | SRS·이슈 연계와 중요도 규칙 | 후보마다 원문·연결 근거, 사용자가 설명 가능한 규칙 |

## 검토 후보 선별 아이디어

우선 규칙 기반으로 시작한다. 후보마다 선정 이유와 원문 링크를 남겨 사람이 확인할 수 있어야 한다.

- 내용·상태·첨부가 변경된 SRS와 이에 연결된 미해결 이슈.
- 완료 처리 후 다시 열린 이슈, 중요도가 상승한 이슈.
- 변경된 사양과 연결됐지만 최근 검증 기록이 없는 이슈. 검증 기록의 존재·필드 매핑을 먼저 확인해야 함.
- 필수 연결이나 담당자가 없는 항목. 어떤 필드를 필수로 볼지는 운영 기준으로 설정.
- 같은 항목의 같은 변경 버전은 한 번만 알림. 후속 변경이나 긴급도 상승 시 다시 알림.

후보 키는 프로젝트·항목 ID·변경 버전으로 관리한다. 상태는 신규/검토 중/완료/제외로 구분하고, 처리 이력을 삭제하지 않는다. 후보와 연결된 변경 전후 근거도 보존한다.

AI 요약은 후속 선택 기능으로 두고, 원문 외부 전송 정책·사용 모델·비용·실패 시 동작을 먼저 결정한다. AI가 없어도 수집·비교·규칙 선별·알림이 동작하도록 구성한다.

## 알림과 운영

첫 단계는 일일 요약 알림 한 번과 실행 실패 알림을 권장한다. 채널·수신자·시간·중요도 기준은 구현 전에 확정한다. 중요한 후보를 모두 즉시 알리면 중복과 소음이 커질 수 있으므로 긴급 항목만 별도 즉시 알림을 고려한다.

자동 실행은 단일 잠금 아래 수집·검증·선별·알림을 순서대로 수행한다. 네트워크 중단, 수집 누락, PDF 실패, 알림 실패를 서로 다른 상태로 기록하고 제한된 재시도와 복구 절차를 제공한다.

## 적용 순서와 통과 기준

1. 완료한 로컬 기반 검증: 누락·PDF 실패·0건·제한 수집·동시 실행 테스트가 각각 기대 상태를 반환.
2. 제공 중인 관찰 이력과 후보 저장: 재실행해도 후보·알림 중복 없음, 처리 상태 유지.
3. 알림을 보내지 않는 관찰 모드: 여러 실행 결과에서 후보 선정 이유를 사람이 검토.
4. 사용자 기준을 반영한 제한적 알림 운영: 실패 알림·중복 방지·재시도 검증.
5. 예약 완전 자동화: 실제 운영 주기를 확인한 뒤 기존 이슈 저장소와 원본 폴더 정리 판단.

현재 코드 검토와 테스트만으로 실제 서버·수신자까지 포함한 무결점 운영을 보장하지 않는다.
